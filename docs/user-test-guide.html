Before you start

Set up a safe test workspace

Snatchi has two surfaces: the web app (organisation owners, managers, guests and admins) and the engineer mobile app. Most workflows cross both, so read this section first and agree the test accounts with the coordinator before you click anything.

Payments and real-world side effectsConfirm with the coordinator that Stripe is in test mode before entering any card. In test mode, use Stripe’s test card 4242 4242 4242 4242, any future expiry, any 3-digit CVC and any postal code. Never enter a real card, real bank details or real identity documents. Emails and push notifications reach real inboxes and devices, so use test mailboxes only.

Ground rules

  • Work through the sections in order. Later sections reuse the project, engineer and booking you create earlier.
  • Tick the box beside each step as you go. Your progress is saved in this browser only.
  • Each step has an Expect line. If reality differs, that is a finding, so stop and report it (see Reporting).
  • Use a current Chrome, Safari or Edge browser, and repeat key screens at a mobile width (about 390px).
  • Upload only harmless sample files with no customer or employee personal data.
Needs a second testerSeveral journeys need two people at once, for example an owner creating a booking while an engineer accepts it on a phone. Those steps are marked Needs a second tester. If you are alone, you can test only the steps up to the hand-off.
Web · no account needed

Public website, sign-up and sign-in

The first impression and the front door. Test these before signing in as any role.

A. Browse the public website

No sign-in needed. The site should explain AV project, engineer and booking management clearly and make the next action obvious.

  1. Open the homepage. Review the header, logo, headline, calls to action, footer and mobile layout.Expect Logo is crisp and sensibly sized, no overlapping or cut-off text, no placeholder or stock-template content.
  2. Open Features, Pricing, About and Contact from the navigation, then the Privacy Policy and Terms and Conditions from the footer.Expect Every link loads a real page. No 404s, no broken images.
  3. Review the three pricing cards. Compare the price, billing period and limits with the Plans table.Expect The figures match exactly.
  4. Open the Contact form and submit it empty, then with an invalid email, then with clearly marked test content (QA-...).Expect Validation messages appear for the empty and invalid cases. The valid submission shows success feedback and produces exactly one email.
  5. Use the browser’s back/forward buttons and reload on each page.Expect Pages restore correctly with no blank screens.

B. Subscribe and create an organisation

This is how a new organisation owner joins. Do this in a test environment with Stripe test mode confirmed.

  1. On Pricing, choose a plan.Expect You arrive at the secure checkout. The summary shows the plan name, price and billing period you picked.
  2. Leave Company, First name, Last name, Email and Mobile empty and try to continue.Expect The Pay securely button stays disabled until the terms are accepted, and required fields are validated.
  3. Fill every field with test details. Use a mailbox you can read. Enter the Stripe test card. Tick the Privacy Policy and Terms and Conditions box.Expect The button enables. Both policy links open the right pages.
  4. Click Pay securely.Expect The button shows “Processing secure payment…”, then you land on the success page saying your account is ready and that a temporary password was emailed.
  5. Open the email. Confirm there is exactly one welcome/temporary-password email, addressed correctly, with no raw template tags.Expect One email, correct recipient and branding.
  6. Click Back to pricing (or repeat the checkout) with the card number 4000 0000 0000 0002.Expect The payment is declined with a clear message and no account is created.
  7. Try to subscribe again with the same email you already used.Expect The system handles it gracefully (clear message or existing-account handling), with no duplicate organisation.

C. Sign in, reset password and sign out

  1. Open Sign In. Submit empty, then with a wrong password.Expect Clear errors, no hint about whether the email exists, and no crash.
  2. Use the eye icon in the password box.Expect Password toggles between hidden and visible.
  3. Sign in with the owner email and the temporary password.Expect You reach the owner dashboard. If the app asks you to change the password, follow it.
  4. Sign out, then click Forgot Password?, enter your email and submit.Expect A reset email arrives (one only).
  5. Open the reset link, set a new password, then sign in with it.Expect The old password no longer works. The new one does. Reusing the same link a second time is rejected.
  6. While signed in, change the address bar to /protected/admin/dashboard.Expect You are denied. You must not see any admin screen.
  7. Sign out, then press the browser Back button.Expect Protected data is not shown. You are sent to sign-in.
Web · organisation owner

Run the organisation workspace

The owner can do everything in the organisation. This is the longest section. Work A to I in order, because each step builds the data the next one needs.

A. First sign-in and getting started

Sign in as the organisation owner.

  1. Look at the Dashboard after signing in. Dismiss the welcome message if one is shown.Expect The dashboard loads quickly and shows only your organisation’s data. The welcome message does not return after dismissal.
  2. Open the Dashboard tour and step through it to the end, then close it.Expect Each tour step highlights the right area. Closing the tour works at any step.
  3. Find the getting-started checklist: complete the organisation profile, add an engineer, create a project, schedule an engineer.Expect Each item links to the right screen. Items tick off when you complete them.
  4. Check the summary tiles (projects, team, bookings).Expect Counts are zero or match what you create below, and update after you add records.
  5. Open Help & Guides at the bottom of the sidebar. Search for “invoice”.Expect Guides are listed by category, search narrows them, and each guide has an action button that opens the right page.

B. Settings, subscription and password

  1. Open Settings. Confirm the four sections: Profile, Subscription, Receive payments, Password.Expect All four are reachable and the URL reflects the section.
  2. In Profile, change the organisation description or contact detail, save, reload.Expect The change persists. Invalid values (bad email or mobile) are rejected with a message.
  3. In Subscription, check the plan name, billing period and status against the Plans table.Expect Plan and status are correct.
  4. Open the Stripe customer portal only if the coordinator approved billing tests. Look but do not cancel or change the plan.Expect The portal opens for your organisation and you can return to Snatchi.
  5. In Receive payments, review the Stripe Connect status. Do not submit real identity or bank data.Expect The status (not started / pending / verified) is clear and the next action is obvious.
  6. In Password, change the password using a wrong current password, then the right one.Expect The wrong one is rejected. The right one succeeds and you can sign in with the new password.

C. Build your team (Users)

The owner adds engineers, managers and guests. Engineers sign in on the mobile app.

  1. Open Users, then Add user. Choose the Engineer role, enter a name and a unique test email, and set an address.Expect The form validates required fields. Saving shows the new engineer in the list.
  2. Try to add another user with the same email.Expect Rejected with a clear message. No duplicate is created.
  3. Set visibility (whether the engineer appears in the external network) and enable Chat Status. Save.Expect Both settings persist after reload.
  4. Add a Manager and, if you have one, a Guest, each with their own test email.Expect Each appears with the correct role.
  5. Check the engineer’s mailbox.Expect They receive one invitation or credentials email, with correct branding.
  6. Use Search team members by name and by email. Page through the list.Expect Results narrow correctly. Paging works and counts are consistent.
  7. Click Edit User on the engineer, change the phone number, save.Expect The update shows in the list and on re-open.
  8. Click View user documents.Expect The documents panel opens (it may be empty). Closing it returns you to the list.
  9. Toggle Active Status off for a spare test user.Expect The user is disabled but historical records remain. They can no longer sign in.
  10. Click Delete User on a spare test user and confirm.Expect A confirmation appears first. After confirming the user is gone or disabled and nothing else is affected.

D. Create and manage a project

A project must exist before an engineer can be booked.

  1. Open Projects, then Create project.Expect The form opens with fields for name, number, scope, address, priority, status and dates.
  2. Submit with everything empty.Expect Each required field shows an error and nothing is saved.
  3. Fill in project name (QA-...), project number, scope of work, address line 1, choose a priority (Low / Medium / High) and status, and set start and end dates.Expect Valid data is accepted.
  4. Set the end date before the start date and save.Expect Rejected with a clear message.
  5. Correct the dates and save.Expect You are returned to the project list and the new project appears. The summary tiles (Total projects, In progress, Completed) update.
  6. Use Search projects with part of the name, then the Select Status and Select Priority filters, then the date range. Use Clear project date range.Expect The list narrows each time and returns to the full list when cleared.
  7. Click Edit Project, change the scope and priority, save, reload.Expect Changes persist.
  8. Click Add Documents to project and upload a small harmless image or PDF.Expect Upload progress shows, then the file appears in the list. Open it to confirm it displays.
  9. Try a file larger than your plan’s per-file limit.Expect It is rejected before storage with a useful message (see Plans).
  10. Remove only that document.Expect The document is deleted and the project is intact.
  11. Click Add Team to project and add your test engineer.Expect The engineer is listed against the project.
  12. Change the project status to Completed, then back.Expect Status updates everywhere it is shown (list, tiles, edit screen).

E. Book an engineer (single day)

Needs the project from step D and the engineer from step C. For the engineer’s side, see the Engineer app.

  1. On your project, click Book engineer.Expect The engineer search opens for that project.
  2. Start on My engineers. Search by the engineer’s name.Expect Your internal engineer is listed with services and rate information.
  3. Switch to External engineers and search by a location.Expect Only engineers who chose to be visible are shown. Switch back to My engineers.
  4. Click View availability on your engineer and pick a free date and time.Expect The scheduler opens with the project and engineer already chosen.
  5. Confirm the title, rate, offer and job description. Try saving with the title empty first.Expect Required fields are enforced. A complete form is accepted.
  6. Create the booking.Expect It appears in Pending with the right project, engineer, date, time and rate.
  7. Create a second booking for the same engineer at an overlapping time.Expect Rejected with a clear message. Overlaps are not allowed.
  8. Check the engineer’s mailbox and phone.Expect One notification or email about the new booking, with no duplicates.

F. Multi-day booking

  1. From the project booking flow open the engineer’s availability again.
  2. Choose a first date and last date a few days apart, and set the daily start and end time.Expect The generated working days are listed so you can review them.
  3. Submit once.Expect One linked schedule entry is created per working day, not one long booking.
  4. Open the booking list and remove one day.Expect Only that day is removed. The other days remain.

G. Follow a booking through its statuses

Use Bookings (the booking list) and the scheduler. Needs a second tester for the Accepted step, unless the coordinator can act as the engineer.

  1. Open the booking list and find your booking.Expect Status is Pending. The booking shows project, engineer, date, time and rate.
  2. After the engineer accepts on the mobile app, refresh the list.Expect Status becomes Accepted with no duplicate rows.
  3. For an internal engineer, check whether any further approval or payment step is required.Expect The next action is obvious and only the party who must act can act.
  4. At the agreed time the engineer moves the job to Ready to Start, In Progress, then Completed.Expect The web status follows the same order with sensible timestamps. Skipping a step is blocked.
  5. Click Open Conversation on the booking.Expect The booking chat opens with the right participants.
  6. On a separate disposable booking, use Delete Schedule (cancel).Expect A confirmation appears. The booking becomes Cancelled and the engineer cannot continue it.
  7. Have the engineer decline another test booking.Expect The booking becomes Declined and stays visible for audit.

H. Chat

Needs a second tester (engineer on mobile) for delivery checks.

  1. Open Chats. Use the Direct and Groups tabs.Expect Each tab lists only its own conversation type.
  2. Click New chat and start a conversation with your test engineer. Send a message containing a unique marker such as QA-hello-1.Expect The message appears once and in order.
  3. Check the engineer’s mobile app.Expect The same message appears once, within a few seconds.
  4. Reply from the phone.Expect The reply appears once on the web, in the right order.
  5. Click New group, name it QA-group, add two test users, send a message.Expect Everyone added receives it. People not added do not.
  6. Use Search conversations by a participant and by a group name.Expect Results narrow correctly.
  7. Refresh the page mid-conversation.Expect History reloads in full, with no duplicates.

I. Invoices and payments

  1. Open Invoices. Use Search invoices and the date range.Expect The register narrows. Clear date range restores it.
  2. Open an invoice.Expect It shows engineer, project, dates, line items, tax and total. The totals add up.
  3. Change the Invoice status only when you can justify it (e.g. mark a test invoice paid).Expect The change saves and the register reflects it. The booking’s operational status is not altered by it.
  4. Download the invoice as PDF, then as CSV.Expect Both files open. Amounts and names match the screen.
  5. Export the filtered invoice register as CSV.Expect The file contains only the filtered rows.
  6. Open the payments made and payments received lists and a single payment detail.Expect Amounts, engineer, project and dates match the booking. No duplicate payment appears.
Web · manager

Manager access

A manager works inside the same organisation. The key test is that they can do their job and cannot see or change what belongs to someone else.

Manager checks

Sign out of the owner account, then sign in as the manager (same organisation).

  1. Open the Dashboard.Expect You see the same organisation’s data as the owner and nothing from any other organisation.
  2. Open Projects and edit the owner’s QA- project (change the priority).Expect The edit saves. The owner sees the change.
  3. Open Users and view the team.Expect The list matches the owner’s view. Record what you can and cannot change. Anything not intended for a manager is a finding.
  4. Open Chats and send a message to the engineer.Expect Delivered once to the engineer app.
  5. Open Invoices, filter by date and export CSV.Expect The export contains your organisation’s invoices only.
  6. Open Settings.Expect Record which sections you can see. Changing the organisation’s subscription or Stripe details should be an owner-level action. Report anything surprising.
  7. Paste an owner-only or admin URL (e.g. /protected/admin/dashboard) into the address bar.Expect Access is denied.
Mobile · engineer app

Test the engineer app in the field

Engineers do not use the web app. They receive bookings, chat, update progress and invoice from their phone. Use a real device where you can.

Mobile evidenceEvery mobile report must include device model, OS version, app build, network type (Wi-Fi/mobile data) and whether notifications are allowed.

A. Sign in and set up the profile

  1. Install the supplied build and open it. Complete any first-run intro screens.Expect The app opens with no crash.
  2. Tap Sign in with an empty form, then with a wrong password, then with the engineer’s credentials.Expect Clear errors for the first two. A successful sign-in shows the Home tab.
  3. When asked, allow notifications and location on this test device only.Expect The prompts are understandable. Declining does not break the app.
  4. Open Settings and review the profile. Update an approved field and tap Save profile.Expect The change saves. The profile belongs to the right organisation and no other user’s data appears.
  5. Open the address screen, enter an address and tap Save address.Expect The address validates and saves.
  6. Add a harmless profile document or photo.Expect Upload progress shows. The file can be re-opened and deleted. Check the owner can see it under View user documents on the web.
  7. Use the forgot password option on the sign-in screen.Expect A reset email arrives. Do not paste codes into screenshots or tickets.

B. Service rates

Rates are what owners see when they search for engineers.

  1. In Settings, open service rates. If empty, tap Add first rate, otherwise Add service rate.Expect The rate form opens.
  2. Enter a service, a rate and any details. Try saving with the rate empty first.Expect Required fields are enforced.
  3. Tap Save rate.Expect The rate appears in the list.
  4. On the web, as the owner, search for this engineer in Book engineer.Expect The new rate is visible.

C. Receive, accept and decline bookings

Needs a second tester: the owner creates the bookings from the Owner section E.

  1. Have the owner create a booking. Open the Bookings tab on the phone.Expect The booking arrives within a short time, with project, location, dates, times, description, rate and offer all correct.
  2. With notifications allowed, tap the booking push notification.Expect The app opens on the right booking. With notifications denied, the booking still appears in the list.
  3. Tap Accept booking and confirm.Expect It moves to Accepted. The owner’s web list changes from Pending to Accepted.
  4. Have the owner create a second booking. Tap Decline booking on it.Expect It becomes Declined on both sides. Neither side can reopen it.
  5. Try to accept a booking that the owner has already cancelled.Expect The app explains it is no longer available and does not crash.

D. Do the job: progress and location

Run this at the agreed time with an eligible booking. Location-based steps need a real device.

  1. Open the accepted booking on or just before its start time.Expect Details match the web.
  2. Try to start the job long before the start time.Expect It is blocked with a clear message (invalid early transition).
  3. At the agreed time move the booking to Ready to Start, then In Progress.Expect Each change is reflected on the owner’s web booking list within moments.
  4. If the job requires being on site, test with location allowed and then denied.Expect With location allowed the on-site check works. With it denied the app explains what is needed.
  5. Open the project details and upload a work photo from the project screen.Expect The photo uploads and shows on the project on the web.
  6. Move the job to Completed.Expect Status is Completed on the web with a sensible timestamp. No further changes are possible.

E. Messaging

  1. Open the messaging tab. Confirm direct chats and the booking chat are listed.Expect Conversations match what the owner created.
  2. Receive the owner’s message and reply. Send an image if supported.Expect Messages are in order, not duplicated, and show on web.
  3. Put the app in the background, have the owner send another message.Expect A push notification arrives and opens the right chat.

F. Invoices

  1. Open the invoice tab and start a new invoice for the completed booking.Expect The project, dates and rate are pre-filled correctly.
  2. Tap Add line item and add an extra item. Tap Save draft.Expect The draft saves. Totals and tax recalculate correctly.
  3. Submit the invoice.Expect It appears on the owner’s web Invoices with matching amounts.

G. Sign out and security

  1. Sign out, fully close and relaunch the app.Expect Protected data is not visible. You are asked to sign in.
  2. Sign in as the engineer, then have the owner disable that engineer on the web.Expect On the next app action the engineer is signed out or blocked.
  3. Turn on airplane mode and open Bookings.Expect The app shows a clear offline message rather than a blank or crashing screen.

Web + mobile · two organisations

External engineer booking and payment

Eligible bookings with engineers from another organisation require payment before work can start. This is the most sensitive workflow in the product.

Test mode onlyThis journey touches Stripe Connect and card payments. Run it only in an environment the coordinator has confirmed is in Stripe test mode, with disposable organisations. Never use real card or bank data.

External engineer booking and payment

Needs two organisations: Organisation A (the buyer, owner signed in) and Organisation B (owns the external engineer). Needs a second tester.

  1. As Organisation B’s owner, open Settings → Receive payments and complete Stripe test onboarding.Expect Status becomes verified and payouts/charges are enabled.
  2. Make one of B’s engineers visible in the external network (user visibility setting) and add a service rate.Expect The engineer is eligible to be booked externally.
  3. As A’s owner, open Book engineer on a project and switch to External engineers. Find B’s engineer.Expect Only visible engineers appear, with their rate.
  4. Create the booking.Expect Status is Pending. B’s engineer is notified.
  5. B’s engineer taps Accept booking on the mobile app.Expect A’s list shows Accepted, then Awaiting payment.
  6. As A’s owner click Pay for Service on the booking and pay with the Stripe test card.Expect The payment succeeds. The status becomes Ready to start. No duplicate payment or notification is created.
  7. Check payments made (Organisation A) and received (Organisation B).Expect Both lists show the same amount and booking. Totals are correct.
  8. Retry Pay for Service with the declined test card 4000 0000 0000 0002, on a second disposable booking.Expect The failure is explained, nothing is charged, and the booking stays Awaiting payment so you can retry.
  9. Complete the job as in Engineer section D.Expect Both organisations see Completed, and the invoice reflects the right engineer, project and amount.
Web · platform admin

Platform administration

Admin is a separate control plane. The tests focus on isolation, read-only customer data and safe, reasoned actions.

Admin is intentionally isolatedThere is no public admin sign-up. Only an authorised operator provisions an admin and shares access privately. Never share admin credentials in a ticket, screenshot or this guide. Do not suspend real customers, change subscriptions or touch live transfers during testing. Use a disposable test organisation only.

Admin checks

For the authorised tester who has been given the admin account.

  1. While signed out, open /protected/admin/dashboard. Then sign in as a normal organisation user and try it again.Expect Both are denied.
  2. Sign in as the admin and review Dashboard.Expect Platform-wide figures load. Nothing shows a single organisation’s private data inappropriately.
  3. Open Users. Search and page through.Expect Customer users are read-only here. No edit or delete controls appear for them.
  4. Open Organisations. Use Search organisations by name, email, mobile and plan.Expect Search matches each field. Paging works.
  5. On your disposable test organisation, open its record and review owner, plan and status.Expect The details match what the owner sees in Settings.
  6. Try the suspend action without entering a reason.Expect It is blocked. A reason is required.
  7. Enter a reason, suspend the test organisation, then sign in as its owner.Expect Protected lifecycle actions are blocked with a clear message. Existing data is still viewable per policy.
  8. Reactivate the test organisation.Expect The owner regains normal access.
  9. Open Payment issues.Expect Failed payments and webhook/transfer failures are listed with payment ID, status, amount and created time.
  10. Open a single payment detail from the list.Expect It shows the payment, transfer status and failure reason.
  11. Open Settings and review platform configuration (support email, telephone, public identity, error monitoring, transactional email).Expect Values display correctly. Do not change them in a shared environment.
Coordinated acceptance tests

End-to-end journeys

These tie everything together. Run them after the individual role sections pass.

Subscribe→Add engineer→Create project→Book engineer→Engineer accepts→Chat→Work starts→Work completes→Invoice

Journey 1: One booking from sign-up to invoice

The single most important test. Two testers: Owner (web) and Engineer (phone). Record the time and screen of any step that differs from Expect.

  1. Owner: subscribe to a plan and sign in with the temporary password.Expect Dashboard loads. Checklist shows nothing complete.
  2. Owner: Settings → Profile: complete the organisation profile.Expect Checklist ticks “profile”.
  3. Owner: Users → Add user → Engineer with the engineer tester’s email, chat enabled.Expect Engineer appears. Checklist ticks “add an engineer”. Engineer gets one email.
  4. Engineer: sign in on the phone and save the profile and address.Expect Profile is saved and visible on web.
  5. Owner: Projects → Create project QA-..., add a document and add the engineer to the team.Expect Project, document and team saved. Checklist ticks “create a project”.
  6. Owner: Book engineer → View availability → create the booking.Expect Booking is Pending. Checklist ticks “schedule an engineer”.
  7. Engineer: open Bookings → tap Accept booking.Expect Owner’s web list moves to Accepted within moments.
  8. Both: exchange a chat message each way from the booking conversation.Expect Each message appears exactly once on the other side.
  9. Engineer: at the agreed time: Ready to Start → In Progress, upload a photo, then Completed.Expect Web shows each status in order, the photo, and sensible timestamps.
  10. Engineer: create and submit an invoice.Expect It appears on the owner’s Invoices page.
  11. Owner: open the invoice, update its status, download PDF and CSV.Expect Amounts, engineer, project and dates all match the booking.
  12. Owner: sign out. Engineer: sign out.Expect Both are returned to sign-in with no data left visible.

Journey 2: Change of plan (cancel and decline)

  1. Create three bookings for three different slots.Expect All three are Pending.
  2. Engineer accepts the first, declines the second. Owner cancels the third.Expect Statuses are Accepted, Declined and Cancelled. Declined and Cancelled are final.
  3. Try to open the chat or change the status of the Declined booking.Expect No further workflow is possible.
  4. Check invoices.Expect Cancelled or declined bookings create no invoice and no payment.

Journey 3: Two organisations

Follow the full External engineer booking and payment workflow from start to Completed.

  1. Confirm both organisations only ever see their own projects, users and invoices throughout.Expect No cross-organisation data leaks anywhere, including search results and chat lists. A leak is a critical defect.

Quality checks

Cross-cutting checks

Small things that make a product feel finished, and tenant-safety checks that matter most.

Checks on every screen

Do a quick pass of these as you work, not as a separate round.

  1. Resize the browser to about 390px wide, or use a phone.Expect No horizontal scrolling, nothing cut off, and the menu works.
  2. Try Chrome, Safari and Edge for the owner journey.Expect Behaviour is the same in all three.
  3. Submit forms twice quickly (double-click).Expect Only one record is created.
  4. Reload mid-way through a form and in the middle of a booking.Expect Nothing is lost or duplicated unexpectedly.
  5. Leave a signed-in page idle for a long period, then act.Expect You are asked to sign in again and nothing is corrupted.
  6. Navigate with the keyboard only (Tab / Enter / Esc) on sign-in and the project form.Expect Focus is visible, order is logical, and dialogs close with Esc.
  7. Look for text errors: typos, wrong brand names, placeholder text, wrong currency.Expect Everything reads as Snatchi, in pounds (£), with correct spelling.
  8. Try to open another organisation’s record by editing an ID in the address bar.Expect It is refused. No data from another organisation appears.
